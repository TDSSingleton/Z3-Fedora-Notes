THREE SECTION-18 "TRAPS" THAT TURNED OUT NOT TO EXIST:
  - adreno_smmu failing with -110 was deferred_probe_timeout=1 expiring
    while gpucc is a module loaded from userspace. At 60 it binds fine.
  - a660.1 declares no speedbins, so nothing reads the TZ-owned qfprom
    "speed_bin" nvmem cell; a6xx_set_supported_hw() treats -ENOENT as OK.
  - the GMU has no qcom,qmp and the GPU has no interconnects: no AOSS or
    icc dependency.

MODULE PARAMETER THAT IS NOT OPTIONAL:
  insmod msm.ko separate_gpu_kms=1
  msm_gpu_no_components() returns the separate_gpu_kms module param with NO
  CONFIG_DRM_MSM_KMS guard, so by default adreno_probe() calls component_add()
  and waits forever for a KMS master that a GPU-only build never creates. The
  device then shows as BOUND to the adreno driver, prints nothing at all, and
  creates no DRM device. Pinned in /etc/modprobe.d/msm-gpu.conf on the rootfs.

WHAT THIS DOES NOT DO:
  It does NOT make the UI fast. KWin still composites 2208x1768 through
  kms_swrast on simpledrm: simpledrm has no render node and is not one of
  Mesa's kmsro display drivers, so GPU-rendered buffers have no path to it.
  That needs DPU + DSI + the S6E3XA2 panel, which replaces simpledrm.
